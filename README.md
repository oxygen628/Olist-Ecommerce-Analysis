# Olist 电商全链路经营分析与履约诊断

##  项目背景
本项目基于 Olist 十万级真实电商数据集，旨在解决平台**“经营全貌缺乏全局洞察、履约链路存在转化断点、头部卖家效能与规模不匹配”**的核心业务痛点。通过数据清洗、数仓建模、性能优化及可视化看板，输出数据驱动的业务决策。

##  技术栈
*   **数据清洗与处理**：Python (pandas, numpy)
*   **数据库与性能优化**：MySQL 8.0 (窗口函数, CTE, 执行计划 EXPLAIN)
*   **数据可视化**：Power BI, DAX
*   **分析报告**：Markdown, PDF

##  目录结构
*   `python/`：包含数据探查、清洗加工与入库的 Python 脚本。
*   `sql/`：包含建表 DDL、核心业务分析查询、数据质量校验及性能优化 SQL。
*   `dashboard/`：包含 Power BI 构建的 3 页核心业务驾驶舱截图。
*   `report/`：包含完整的业务分析诊断报告 PDF。

##  核心业务洞察
1. **履约断点**：支付批准至发货环节流失 605 单，平均发货耗时 66.7 小时，整体延迟率 8.11%。
2. **高营收掩盖低服务**：发现某头部卖家 GMV 达 23.8 万，但延迟率 13.36%，评分仅 3.35 分，存在严重风险外溢。
3. **复购黄金窗口**：整体复购率 3.04%，但 0-30 天内复购用户达 1633 人，是精准营销的最佳节点。

##  技术亮点：MySQL 性能优化
针对月度 GMV 查询，通过 `EXPLAIN` 发现状态过滤导致索引失效与全表扫描；采用**空间换时间**策略，设计预计算汇总表，将核心查询耗时从 **1.97s 降至 0.5ms**（提升约 4000 倍）。
